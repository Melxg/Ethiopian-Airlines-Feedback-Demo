---
name: Feedback prototype boundary
description: Product boundary for the Ethiopian Airlines passenger-feedback HCI prototype.
---

The prototype should demonstrate the passenger-to-agent HCI workflow without depending on external services: local persistence is sufficient, and sentiment remains visibly simulated.

**Why:** The purpose is course evaluation of usability and interaction design, not production infrastructure or model accuracy.

**How to apply:** Preserve the offline demo path when extending the app; only add backend, authentication, AI, or third-party integrations if the user explicitly changes the scope.
